2Light theme, closing a ticket, recovery states
  • The light theme uses the same layout with a warm off-white palette. Switch themes live in Settings › Appearance, in any window.
  • "Close ticket…" in any ticket header opens the confirmation. It lists every step and every file that gets merged, including code. Confirming plays the steps through to the end.
  • Recovery has one home: the red "need attention" item in the footer. Each entry says what's wrong, confirms your work is safe, and gives one action. Activity shows the same actions.
  • When an item needs fixing, a banner appears above its editor: a conflict on MH-VH-6PJ, a missing type on "quick note from standup", or a file that isn't managed yet (notes-ssh.md).

1Manyhands desktop workspace: layouts, docked tabs, sheets
  • Every window is clickable. Footer icons show/hide panels (left side = left and bottom docks, right side = right dock). Click repos, projects or teams to change the scope, sort ticket columns, expand folders, open and close tabs, split the editor.
  • One scope at a time. It appears in the title bar and in the footnote under the ticket list.
  • Plain language throughout: "Editing · saved on this computer", "2 to share", "Can't reach". Hover any repo, row or state pill to see the Git details (branch, worktree, remote).
  • Dark theme only, because the theme question was skipped. Linux client-side window controls. Brand amber marks focus and selection; the teal is lightened for dark backgrounds.
  • The ticket and document editors are placeholders, as you asked. Only the header and lifecycle actions are sketched (Save, Share, Close ticket / Approve and merge).
  • Sample data comes from Manyhands' own tickets and docs, plus three made-up repos (site, handbook, zorite fork) so the sync states and nonconforming items have something to show.
