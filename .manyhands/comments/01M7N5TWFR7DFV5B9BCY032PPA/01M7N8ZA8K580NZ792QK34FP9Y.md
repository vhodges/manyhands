Implementation done, 2026-11-17 (commits 4b72beaf and e39fc726). A nonconforming file opened by its path now reads in the same read-only Zorite view as an item's body (`nonconforming_file` in `page.rs` is the one predicate). Its Git details (Context, Branch, Worktree, Head commit) are out of the page and in the details sheet's Git details mode, opened by one new header button, "Git details" (`sheet/git.rs`). A file with context problems has no provenance and no button. Closing the repair view returns focus to the read view.

**Ruling.** Only nonconforming files change. An Inspect tab of a conforming item (the "Inspect the raw front matter" link) keeps the raw textarea and its provenance, since a raw view should not be reformatted as markdown. Cost if wrong: one predicate to widen.
