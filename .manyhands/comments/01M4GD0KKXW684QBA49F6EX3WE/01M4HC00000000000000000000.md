Starting implementation in the ticket worktree after fetching origin/main and
rebasing the ticket branch onto it. The CLI has no ticket/comment operations,
so checkpoints are recorded in the canonical filesystem paths.

First checkpoint: remove the public synchronization fixture's post-save index
refresh and run its context-first-publication case before changing production
code. The isolated commit index in checkpoint_owned_paths currently never
writes the worktree index. Implementation will refresh only the owned entries
from the committed snapshot while the existing save lease is held.

No-change saves will also attempt the same repair, allowing a later save to
recover from a previous index.lock failure. A failed index update after the
authoritative commit will be best-effort: the save retains its existing success
and discovery-refresh reporting, without rollback or a new public outcome.
Verification will explicitly exercise the lock failure and later repair.
