workflow for Cycle 04.

At desktop startup, an eligible selected protected key uses the one shared
process credential provider. The existing transport first tries without a
secret, then the desktop presents one deduplicated masked ambiguity-aware
unlock prompt when required. Successful credentials remain only in that
process's session and are reused by manual and automatic polls. Process exit,
selection/source change, or explicit clear invalidates the cache.

Cancellation/provider failure produces session-only unlock-required state:
automatic attempts suspend without repeated prompts and do not change durable
explicit pause. Unknown or changed host trust remains an independent explicit
exact-fingerprint approval, never an automatic unlock/backoff path. Wave 03
owns desktop prompt/status presentation; Cycle 04 supplies the session-aware
headless observation contract and tests. Implementation remains unapproved.
