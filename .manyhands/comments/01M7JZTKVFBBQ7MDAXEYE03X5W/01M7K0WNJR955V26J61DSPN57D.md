Checkpoint 2026-11-16, two fixes committed on the ticket branch.

**Confirmed by the owner:** the prompt-every-poll symptom on a passphrase-protected key. After unlock, a poll checked both repos; five minutes later the next automatic poll reported the key locked. One of the two repos is the manyhands demo clone, whose `origin` points at an unreachable host.

**Root cause (poll symptom).** `SessionCredentials::with_passphrase` evicted a cached passphrase on any closure failure, and the transport closure reported every connection error (unreachable server, rejected key, network blip) as `PassphraseUseFailure::Unavailable`. The cached passphrase is per key and shared by every repository, so one failing repository emptied it for the rest. A background poll cannot prompt (B5), so the next poll answered `ProviderUnavailable`. `cached_rejection` pinned the eviction. Ruled out: a source-token mismatch between the generated-key unlock and the transport (the key store canonicalizes its home).

**Fixes.**
- d3653998: an unencrypted OpenSSH key (header cipher `none`) returns the real error instead of the ambiguity prompt. Unit test table in `passphrase_need_tests.rs`; SSH case `wrong_plain_key_prompts` became `wrong_plain_key_is_rejected_without_prompt`.
- 5605fe3b: `PassphraseUseFailure::Unrelated`. A cached (proven) passphrase is evicted only by a change under it (selection, key source, endpoint, host trust); a server's rejection reads as `KeyRejected`. Tests: `an_unrelated_failure_keeps_a_cached_passphrase_and_caches_nothing_new` in `session_credentials`, `operation_passphrase_tests.rs`, and SSH case `cached_rejection` became `cached_passphrase_survives_rejection`.

**Verified so far.** The targeted tests above pass; `cargo fmt --check` and `clippy --all-targets --all-features -D warnings` are clean. The fast tier and all 11 SSH-harness targets are running on the final tree.

**Open.** A poll that fails because the server rejected the key probably still surfaces as a locked key (`UnlockRequired`) in the UI, which misleads when the passphrase is fine. Worth its own ticket.
